# ADR 0012 — 会話メモリーと再開可能な段階分析

日付: 2026-09-14 / 検証更新: 2026-09-15 / 状態: Accepted（GA4 Pilot、実GA4 Acceptanceは別途）

## 現状と目的

直近4発言・最大8sectionという計画入力の投影だけでは、過去の目的・対象を復元できない。Workspaceの残タスクも質問ごとに初期化されていた。v1.2、ADR 0009の認証・DSS／Grant／Stream境界を維持し、作業記憶、検索用分析履歴、確認済み合意、依存関係を持つ調査計画を分離する。

## 決定

- `WorkingMemory`は目的・ユーザー方針・対象・未検証仮説・確認事項を分類し、発言IDと出所を付ける。ルール抽出に加えDirectorは現在のユーザー発言から引用箇所を選べるが、文字列の完全一致がない抽出は保存しない。数値の真偽は認定しない。確認済みの数値はFinding／Evidence参照だけを使う。
- `agent_episode`へ分析時の質問、期間、指標、集計軸、フィルター、最大12観測行、Finding／Evidence参照を保存する。UI履歴と異なる検索用投影で、取得Dataset本体の複製ではない。新規分析は逐次保存し、旧Workspaceの保持sectionは次の会話開始時に追加する。既にWorkspaceから除かれた旧分析の全件backfillはこの変更では行わない。
- 検索はowner＋DSSで先に絞り、期間・指標名／ラベル・ページ・日本語文字列の一致で候補を順位付けする。検索候補は最大500件、回答用は最大8件。上限超過をUI／モデルへ通知する。現段階はbounded lexical retrievalであり、全件検索・ベクトル意味検索・完全な長期記憶ではない。新しい外部検索サービスやCloud Storageを作成しない。
- 検索結果ごとに現在のSession所有者／状態／Grant／DSS、Finding所有者、Evidenceの会社／DSS／Dataset／GA4 Propertyを再確認する。保存時のデータソースfingerprintと不一致の記録は再利用しない。別ユーザー・別DSSをCompany一致だけで検索しない。
- 過去の分析には分析期間、比較期間、保存時刻、Semantic version、`historical`を付ける。検索で見つけただけでは新しい分析の達成条件を満たさない。過去結果の説明では検証済みFact参照からコードで数値を表示する。
- `agent_agreements`はowner＋DSS単位。候補→ユーザー確認→確定とする。「覚えて」等の発言は候補に留め、モデルが確定するToolを提供しない。訂正は未確認へ戻し、削除は本文と発言参照を消すtombstoneにする。CASで古いrevisionの操作を拒否し、本文なしの監査を残す。元の会話・過去の回答自体は削除しない。既存SiteContextとの意味的な矛盾は自動解消せず、人の確認事項とする。
- `analysis.grouped_breakdown.v1`は「単独軸で上位対象を確定→各対象内の第2軸→評価」を表す。登録済みカテゴリ軸2つ、順位指標1つ、単一期間、最大10対象、各対象の内訳上位5件。ページ×参照元だけでなく国×端末等にも同じ契約を適用する。異なる期間や複数順位指標、Realtime／Funnelは混ぜず未対応として返す。
- 対象値をLLMに生成させず、順位データの完全な文字列と数値から選ぶ。欠損・重複・非有限数値を受け入れない。各子クエリは親の条件を固定し、観測済みの値を完全一致Filterにする。Property／Streamのフィルターは既存Gatewayに強制させる。
- `StagedPlan`は目的、親条件、選定根拠、対象別取得状態と根拠を保存する。当初の4分析ごとの手動再開はユーザー要件の誤解だったため撤回した。現在は選定1回＋最大10対象を同じ依頼内で自動実行し、確定済みの子クエリをLLMの7判断枠と分離する。探索型分析は4回、調査240秒／全体300秒を維持。復元時もEvidenceとscopeを再確認する。障害後の任意の再開発言は受け付けるが、通常の進行に要求しない。
- 子クエリの最後のページFilterを会話全体の条件にしない。終了時に親の条件だけ戻し、Dataset／Finding／revisionは巻き戻さない。取得ゼロ件はゼロ人数と仮定しない。数値はコードで整形し、改善案は未検証の仮説として述べる。レポート作成は引き続き明示指示のみ。

## 仮定・制約

- 長期合意は個人専用。Company共有記憶、管理者による共有ルールや自動学習は導入しない。
- 作業記憶は40項目、計算済みFinding参照32件。保持上限を超えた場合は通知する。引用の分類精度と自由文の矛盾解決を機械的に保証しない。
- 段階計画は依存関係のある一つの汎用テンプレートであり、任意DAGや自動バックグラウンド継続ではない。複数の同時進行計画、条件変更を伴う途中計画の差分再構築、子分析内のさらに深い再帰は今後の課題。
- API失敗とアプリ予算を区別する。再実行のexactly-onceは保証しないが、保存した成功ステップを再度選ばず、既存Cache／idempotencyを維持する。
- 現在のSourceSet認可はApplication Grantに基づく。GA4での未知の権限削除を履歴検索のたびにGoogleへ問い合わせる設計は追加しない。GA4呼出しは既存OAuth／Gateway検証に従う。
- BigQueryはPending、GCS等のクラウド新規作成は保留を維持する。

## 2026-09-15 — 保存形式の修正と要件差異

初回の複数軸チェックポイントがFirestoreの`InvalidArgument`で失敗した。`required_dimension_groups`はアプリ内では二重配列だが、Firestore Standardでは配列の直接の要素に配列を保存できない（[公式データ型仕様](https://firebase.google.com/docs/firestore/manage-data/data-types)）。Store境界だけ`[{"fields": [...]}]`に変換し、get／list／transaction読取りでは元の契約へ戻す。旧・空の記録の読取り互換を保ち、一括移行はしない。MemoryAgentStoreにも同じ変換・制約を適用する。新たな配列違反は本文を含まないエラーで保存前に拒否する。

「続き」で再開する動作はユーザーの要求仕様ではない。保存エラー修正とは別に、同じリクエスト内で段階計画を自動実行する改修を追加した。取得ごとの認可・総時間制限・中断は維持する。プロセス停止や総時間超過をまたぐ永続ジョブの自動再開は未実装として追跡する。

追加取得禁止の説明依頼は、数字や指標名を含んでも新しい分析として再計画しない。保存済み段階計画とFinding／Evidenceを再認可して文章化する。履歴・段階計画に重複していた結果を文章化入力から除き、Gemini 2.5では思考予算を1024に設定する。文章化の検証は、サーバーがFindingから収集した観測ラベル内の数字だけを例外とし、自由な計測値・未知のURLを引き続き拒否する。失敗時は本文を記録せず検証項目をログへ残す。

保存修正後の検証: Backend 374件・mypy 77ファイル・Ruff成功。ユーザー許可の合成レコード1件で実Firestoreの旧形式拒否、新形式の保存・復元・一覧検索・CASを確認し、検証用レコードを削除した。既存会話・設定は変更せず、顧客GA4も呼び出していない。API／ワーカーへの反映・ソース一致・起動状態を確認済み。

## 検証

### 2026-09-17 — Q2a: 引用の解決と関連検索の分離

実保存履歴で、直前回答の引用元が関連検索の上位8件から漏れるケースを確認した。保存済み回答のFinding IDから元Sessionを直接解決し、Evidence、owner／Company／DSS／Semanticを照合して既存の段階計画検証へ渡す。クライアントやLLMにこの参照を指定する新APIは公開しない。

Finding参照を持たない旧回答だけは同じowner／DSSの最大500episodeをEvidence IDで厳密照合する。取得したepisodeはstep検証でも再利用し、同じ復元処理で再走査しない。引用32件・元Session32件の上限を設け、通常の関連検索8件は増やさない。候補は根拠そのものではなく、Session認可、Property／Stream fingerprint、期間／Filter／数値／全完了stepのEvidence照合を改めて通す。

直接参照の欠損・不一致・権限失効・候補の曖昧性は安全に拒否する。「追加取得禁止」では似た別分析で置換せず、GA4を再取得しない。旧全履歴のbackfillや500件を超える旧形式の完全検索は別課題。実履歴の5対象・6根拠・6表示を追加取得0・書込み0で復元した。回帰・実Gemini・画面・Docker反映の結果は[検証記録](../evaluation/q2a-citation-recovery-2026-09-17.md)を参照。

2026-09-16追補: 新しいセッションにある過去の引用を、今回の段階計画の達成と混同しない。明示的な新規段階分析は型付き計画と既存Cacheを経由して結果を記録する。追加取得禁止の説明は、直前に引用されたEvidenceと一致する保存済み段階計画を一意に選び、順位と全完了子分析の条件・計測値を再検証する。別セッションのStateを現在のStateへ上書きせず、その回答の根拠としてのみ使用する。グラフは元Session／Messageを指すサーバー生成の参照を回答へ保存し、読取り時も同一owner・DSSとデータソースfingerprint／Semantic／Evidence／Cacheを確認する。過去の会話自体は変更しない。本文は最大11分析を対象条件付きで表示し、表示上限を未取得と説明しない。

長い会話の目的・対象保持、作業記憶の引用検証、合意の確認／訂正／削除／競合、検索時の他ユーザー・他DSS・削除済みSession拒否、登録カテゴリを替えた段階分析の途中再開、取得回数、親条件の復元を回帰テストで確認する。UIは合成認証・モックAPIでE2E検証する。実Geminiと実GA4の検証は混同しない。

最終改修を含めてBackend 363件・mypy 77ファイル・Ruff成功。Frontendは型検査・Lint・27単体テスト成功、E2Eは設定済み3件＋未設定2件成功。実Gemini＋合成GA4で段階計画、途中再開、目的・制約を踏まえた既存結果の説明を確認した。2026-09-15にDocker Desktop再起動後のAPI／Web／ワーカーへ反映し、ソースハッシュ一致・起動状態・APIとWebの正常応答を確認した。新しいFirestore履歴検索も診断用owner／DSSの空検索で正常応答を確認した（顧客データの取得・書込みなし）。実GA4の数値突合は未完了。詳細は[todo](../todo.md)の検証・反映状況を参照。
